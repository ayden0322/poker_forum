# Codex(GPT-6 Astra)競猜頁 UI 審查(2026-09-13,唯讀,session 01a09694-f906-7bf0-89ef-ce9b133e2c1b)

## 1. 第一眼診斷

這頁像乾淨的賠率清單，尚未形成「以賽事為中心的論壇」。
最傷的三點：聯盟名稱被擠成直排、賠率比賽事醒目、右欄空榜單佔據重要位置。
「單薄」主要來自**資訊種類少、層次倒置**：五個選項很大，隊伍、時間與討論脈絡卻很弱。
留白是放大器，字級與對比是次因；增加盤口或装飾無法解決。

## 2. 逐區審查

以下畫面觀察以提供的桌機截圖為準；互動與手機問題僅依程式碼判讀。引用簡寫：`PC`＝`apps/web/src/app/predictions/PredictionsClient.tsx`；其餘元件檔名均位於 `apps/web/src/components/predictions/`。

### 頁首標題列與「餘額」

**現況：**截圖左側是「賽事競猜」，右側孤立一顆「餘額 1440 P」。標題與餘額使用 `justify-between`，標題為 `text-2xl`，餘額連向會員中心。（`PC:384–394`）

**問題：**標題缺少操作脈絡；「餘額」沒先說清楚是哪種幣，與截圖頂部另一個幣值需要自行區分。

**具體改法：**

- 標題下補一句 `text-sm text-gray-600`：「選擇賽事，留下你的預測與看法。」
- 餘額改「可用 P 幣 1,440」，數字保留 `tabular-nums`；不放大成資產看板。
- 標題列用 `items-start gap-4`，餘額加 `shrink-0 whitespace-nowrap`。修改位置：`PC:386–394`。

### 聯盟分頁

**現況：**截圖「德甲／英超」分成兩行，「韓國職棒／日本職棒」換行不一致，MLB 則維持單行。程式沒有固定圓形尺寸，而是 `flex gap-2` 搭配 `px-4 py-1.5 rounded-full`，缺少禁止收縮與換行的設定。（`PC:340–351`）

**問題：**這更像被擠壓後形成的圓鈕，不像刻意設計的聯盟識別；讀者必須逐字拼回名稱。

**具體改法：**

- 容器改 `flex gap-1 overflow-x-auto pb-2`。
- 按鈕改 `shrink-0 whitespace-nowrap min-h-11 px-3 rounded-md`，固定邊框 `border`，避免選中與未選中邊框規格不同。
- 保留青綠選中態；不加國旗或聯盟裝飾湊資訊量。
- 主欄補 `min-w-0`，讓捲動限制在分頁列內。修改位置：`PC:340–348、415`。

### 日期分組標題

**現況：**截圖的「9/13（週日）」「9/19（週六）」偏淡、小，容易與一般次要資訊混在一起；程式使用 `text-xs font-bold text-gray-400`。（`PC:367–368`）

**問題：**日期本應是掃描賽程的主要定位點，現在視覺權重低於每一個賠率。

**具體改法：**改成語意化 `h2`，使用 `text-sm font-semibold text-gray-700 flex items-center gap-3`，後接 `h-px flex-1 bg-gray-200` 分隔線。保留現有日期資料，不必先新增「今日熱門」等判定。

### 右欄

**現況：**截圖先看到「本週獲利榜／滿 30 場競猜即可入榜」，再看到玩法；下面大面積空白。進行中競猜在沒有 pending 資料時不顯示。（`PC:183–185、240–246、431–433`）

**問題：**冷啟動時，最顯眼的輔助內容是「尚未形成的競爭」與高門檻，缺少當下可完成的小任務。榜單還把尚未取得資料視為空陣列，這個小卡沒有區分載入與真正空榜。（`PC:236–246`）

**具體改法：**

- `TopFiveCard` 空榜時退出首頁右欄，排行榜入口仍可保留；載入、失敗、空資料分開。
- 右欄優先放個人競猜摘要；零紀錄時用簡短操作說明，不再創造第二張空看板。
- `RulesCard` 正文改 `text-sm leading-6 text-gray-600`，關鍵規則常駐，其他用原生 `details/summary` 收合。現有正文為 `text-xs`。（`PC:270–282`）
- 把「滿 30 場競猜」改為「滿 30 場已結算競猜」，與完整榜單文案一致。（`PC:246`；`Leaderboard.tsx:63–66`）

### 整體比例、留白、字級與色彩

**現況：**截圖主欄是重複白卡與大面積選項，右欄內容短；整體乾淨，但接近工具卡片集合。程式為 `max-w-5xl`、三欄網格中的主二副一；卡片統一 `rounded-xl p-4 shadow-sm`。（`PC:104、384、413–430`）

**問題：**有效資訊密度低，並非所有空間都太大。青綠總量不算不足，主要是分配給了每個未選中的賠率，形成錯誤主角。

**具體改法：**

- 網格試 `lg:grid-cols-[minmax(0,1fr)_280px] gap-5`，移除原本兩側 `col-span`；右欄縮窄，主欄 `min-w-0`。
- 卡片試 `rounded-lg border-gray-200 shadow-none p-3 sm:p-4`，先減少外框重量，不把所有間距砍小。
- 建立層級：頁名 24px、隊名 16–18px、日期與正文 14px、meta 12px；賠率回到 16px。
- 青綠集中在選中、連結與命中狀態。品牌設定確實將 `blue-500` 覆寫為青綠，不能把它誤判為藍色。（`apps/web/tailwind.config.ts:10–21`）

與 PTT／Reddit 現代化調性的距離，在於缺少「可讀的內容標題與上下文」，不是圓角本身。真正有用的補充是單場話題與觀點，而非更多徽章。

## 4. 對圓桌方向的挑戰

**贊成兩層卡片，但反對強制把五個選項塞成一列。**賽事帶應成為主角；操作區縮成橫向標籤加數字即可。桌機有空間才同列，手機維持勝負三格、大小兩格。現有選項本來就有 44px 最小高度，應保留，不為密度犧牲點擊。（`PC:66`）

**反對「討論少於 5 一律寫還沒人討論」。**已有 1–4 則時，這句話不真實，也抹去最珍貴的早期貢獻。建議：

- 0 則：「發起賽前討論」。
- 1–4 則：「查看討論」，有資料時帶一則真實摘要。
- 5 則以上：才補數字；不必預留空計數槽。

此問題直接來自簡報的門檻定義。（`.scratch/ui-review/brief.md:20`）

**贊成我的競猜進度，但它不是冷啟動第一屏的萬靈丹。**目前沒有 pending 就整塊消失；現有摘要呈現的是選項、投入與可能拿回金額。（`PC:183–198`）已讀 `MyBet` 型別沒有比分或比分更新時間，不能將現有畫面換標題便稱為「進度」。（`apps/web/src/lib/predictions.ts:35–50`）

更值得優先設計的是「我的競猜」同時容納進行中與近期結果，讓使用者知道回來能看什麼；比分更新時間必須來自比分資料，不能用頁面載入時間冒充。

**「討論這場」優先於「追蹤這場」。**先把競猜與真實單場討論串接起來；追蹤若沒有保存、回看或通知用途，只會增加按鈕。

**冷啟動先像個好用的競猜工具，同時讓每次使用都能自然接上討論。**簡報記載近 30 天只有 2 人登入、0 筆競猜、0 則回覆。（`.scratch/ui-review/brief.md:14`）此時「像有人」應靠明確署名的編輯賽前觀點與真實討論，不能靠熱度、空槽或假活躍。好用帶來首次完成；結果回看與觀點交流才支撐回訪。

## 6. 手機版

**以下是 class 與元件結構推斷，未實測手機畫面。**

1. **聯盟列是最明確的高風險點。**十個按鈕所在容器沒有 `flex-wrap` 或 `overflow-x-auto`，按鈕也沒有 `shrink-0 whitespace-nowrap`；桌機截圖已出現拆字，窄螢幕更可能擠壓或溢出。（`PC:340–351`）優先依前述方式修正，主欄加 `min-w-0`。（`PC:415`）

2. **長英文隊名可能被截到難辨識。**隊伍列是單行 flex，`TeamLabel` 名稱使用 `truncate`。（`PC:118–121`；`TeamLabel.tsx:12、31`）手機可改 `grid grid-cols-[minmax(0,1fr)_auto_minmax(0,1fr)]`，隊名允許兩行 `whitespace-normal break-words`，徽章固定不縮。

3. **不要再壓小賠率格。**現有可點選格有 `min-h-[44px]`，值得保留。（`PC:66`）大小分左側固定 `w-14` 會吃掉窄螢幕可用寬度，建議把組名移到兩格上方。（`PC:146–147`）
